# LaunchShield

LaunchShield 是一个 iOS 去开屏广告工具：找出其他应用缓存的开屏广告素材，先备份，再原地清成 0 字节并冻结，让开屏广告出不来。清掉的素材都有备份，随时可以还原。

版本 0.1.1（正式版），最低系统 iOS 26.0，SwiftUI。

## 功能

- **跨应用文件通道**：移植 kolbicz/WQFiles 的 WQAccess 容器访问层（worse_query 技术），不使用 dylib 注入。
- **应用列表**：按系统版本自动选通道列出全部应用；iOS 26 上优先走快速通道，万一读不到，还有全盘扫描兜底（开扫前确认、过程有进度、可以中途停、下次能接着扫）。
- **选应用**：「一键勾选」一次选上全部用户应用（游戏除外），也可以在应用列表里单独选。
- **素材扫描**：按广告规则名单扫描已知广告目录，命中的按广告商分类列成清单；规则现为第 6 版，覆盖 22 个分组、236 个广告目录（优量汇、穿山甲、BeiZi、美数、UBIX、趣盟、AdMob、TradPlus、Mintegral、软件自营等）；「深扫」再按目录关键词和全屏图片尺寸翻一遍，找名单之外的疑似素材。
- **规则更新**：广告规则由服务器下发，不用更新应用本身；打开应用时会自动检查，有新规则会弹窗提醒，点一下就更新，也可以随时手动点「更新规则」。
- **找广告（前后对比）**：对目标应用拍快照 → 让开屏广告播一次 → 再拍一次 → 列出「刚新增 / 变大了」的候选，带「疑似广告」自动判定，勾选确认后才处理；也可以先清一遍缓存再拍，底子更干净。
- **文件工具**：大文件榜和按文件名搜索，每个文件带人话标签（疑似广告 / 图片·视频 / 个人内容 / 应用文件）；聊天应用账号目录里的图片、视频是个人内容，一律绕开，不会误清。
- **0 字节替换**：原地截断（保留 inode、属主和属性），改前先备份（记录原路径、大小、MD5），可一键还原并核对 MD5；个别正被占用的文件清不动时自动跳过，其余照常处理。
- **配方与守护**：确认过的目标存为「Bundle ID ＋ 容器内相对路径」；「已守护应用」显示 0 字节＝正常、变大＝已复发、冻结、文件夹占位等状态，每次打开本应用自动复查；守护被系统中断后会自动恢复（悬浮窗保持隐藏）；可按应用结束守护、批量移除、清除已不存在的条目。
- **上锁**：冻结/解冻（`chflags UF_IMMUTABLE`，文件和文件夹都冻）、同名文件夹占位与取消、文件权限调整。
- **备份管理**：备份按应用归并查看，可按应用删除、批量恢复或删除；「全部还原」遇到还原不了的文件会跳过并继续，最后汇总告知。
- **数据上传**：识别数据、找广告结果和运行日志可以上传到收集箱，用来核对并扩充广告规则；上传只在用户点按时发生。
- **检查更新**：只查正式版；打开应用时自动检查，有新版弹窗提醒（同一版本一天最多提醒一次），可在应用内直接下载安装包并看下载进度。
- **日志**：记录每个文件的结果与失败原因，可复制全部，也可导出（导出内容带系统版本、应用版本、设备和共享组）；日志文件自动封顶，只留最近的部分。

## 签名要求（重要）

worse_query 通道依赖 **当前进程实际获得的 App Group 权限**，不按免费 ID、证书或签名工具名称直接判定：

1. 启动时优先通过 `SecTaskCopyValueForEntitlement` 读取当前进程有效的 `application-groups`；如果 SecTask 没有返回组列表，则像 Erosion-CN 一样解析主程序签名 Mach-O 中的 entitlements；
2. 优先检查与应用 Bundle ID 对应的组，再逐个验证其他组的容器 URL、Library 目录创建与打开能力，只使用真正可用的组；
3. `embedded.mobileprovision` 只作为诊断信息，不作为运行时授权来源；重签后以进程有效 entitlement 为准；
4. iOS 26.0–26.6.1 在没有可用组时可回退到已验证的 `bad_query`；其他受支持系统需要可用 App Group；
5. iOS 26.0–26.7.2、iOS 27.0–27.3 beta 1（构建 24C5037i）在当前支持范围内；iOS 27.3 beta 2（24C5049d）及之后的修复版本不再支持 worse_query。实际结果还要通过运行时容器授权验证。

免费 Apple ID / Personal Team 签名如果确实向当前进程授予了可用 App Group，也可以使用 worse_query；如果没有，界面会显示具体原因，不会静默失败或回落到其他存储路径。

## 构建

- 云端：正式版通过 GitHub Actions 的 `workflow_dispatch` 手动触发；运行时手动填写 App 版本号和构建号，默认保留所有历史正式版 Release、Tag 和 IPA。见 `.github/workflows/build.yml`。
- 本地：用 Xcode 打开 `LaunchShield.xcodeproj`，选择 `LaunchShield` scheme，Release，真机或 generic iOS 设备。
- 应用图标在 `LaunchShield/Assets.xcassets/AppIcon.appiconset`，浅色与深色两版均由 `IconDesigns/` 的成品接入。
